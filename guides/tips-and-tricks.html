Tips & Tricks

Common pitfalls and best practices from real SDK usage.

Tips & Tricks

Patterns that work well — and patterns that cause subtle bugs — based on real usage.

Calling Before SIP is Ready

Always wait for on_registered before calling dial(). The SIP UA is not ready until that event fires.

voice.on('sociomileEvent', (event) => {
  if (event.event_name === 'on_registered') {
    // Safe to dial now
    enableDialButton()
  }
})

voice.start()
voice.dial('+62812345678', 'contact-id', 'ext') // SIP not ready yet — will fail silently

Saving Call Sessions and Hanging Up Correctly

There are three call scenarios, each with its own session reference and hangup method. Always store sessions in plain variables — not reactive refs — and always hang up using the correct reference.

// Plain variables — NOT ref() — JsSIP session objects must not be proxied
let callSession = null         // outbound dial
let callSessionIncoming = null // softphone direct incoming

Outbound call — session arrives on on_confirmed:

if (event.event_name === 'on_confirmed') {
  if (event.data?.session) callSession = event.data.session
}

Softphone direct incoming call — session arrives on on_incoming_call (and also on the softphone_event / session_incoming group):

if (event.event_name === 'on_incoming_call') {
  if (event.data?.session) callSessionIncoming = event.data.session
}
// Also capture from softphone_event as a fallback
if (event.type === 'softphone_event' && event.event_group === 'session_incoming') {
  if (event.data?.session) callSessionIncoming = event.data.session
}

Agent-to-agent inbound queue call — no session object needed; SDK manages it internally via on_agent_call_linked.

Hangup — use the right method for each type:

// Outbound call
sdk.hangup(callSession)

// Softphone direct incoming call
sdk.hangup(callSessionIncoming)

// Agent-to-agent inbound queue call
sdk.hangupInbound()

Combined hangup handler (when you need one button to handle both outbound and direct incoming):

function hangup() {
  if (callSessionIncoming) {
    sdk.hangup(callSessionIncoming)
  } else {
    sdk.hangup(callSession)
  }
}

Always clear sessions after the call ends:

if (event.type === 'outbound_event' && event.event_group === 'ended') {
  callSession = null
}
if (event.event_name === 'on_session_ended') {
  callSessionIncoming = null
}
if (event.event_name === 'on_agent_call_unlinked') {
  // no session to clear — SDK manages inbound queue internally
}
Never call hangup() without a session argument when handling a softphone incoming call — it will hang up the wrong session or do nothing.

Showing Hangup Before the Call is Submitted

After dial() is called, the SIP stack takes a moment to register the session. The hangup button should only appear after on_sending fires — not immediately after the user clicks Dial.

// State machine: dialing → ringing → connected
if (event.event_name === 'on_sending') isRinging = true   // show Cancel/Hangup
if (event.event_name === 'on_confirmed') isDial = true    // show Hangup + Hold/Mute
if (event.event_name === 'on_initiate_failed') isRinging = false // hide Hangup

// Show Hangup immediately after dial() — SDK may reject the call before SIP sends
isDialing = true
voice.dial(number, contactId, ext)
showHangupButton() // premature — call may never actually go out

Symptom: Hangup button visible but pressing it has no effect because no SIP session exists yet.

Agent Ready State Surviving Outbound Calls on Break

When an agent is on break and makes an outbound call, two SIP sessions exist simultaneously: the break (ready) session and the outbound session. When the outbound call ends, on_agent_logout_success fires for the outbound session — but the break session is still alive.

Distinguish by event.type: inbound_event means the agent explicitly went unready; api_inbound_event means the outbound SIP session ended while on break.

if (event.event_name === 'on_begin_break_success' && event.type === 'api_inbound_event') isOnBreak = true
if (event.event_name === 'on_end_break_success'   && event.type === 'api_inbound_event') isOnBreak = false

if (event.event_name === 'on_agent_logout_success') {
  if (event.type === 'inbound_event') {
    // Real logout (also fires when unready while on break)
    isReady = false
    isOnBreak = false
  }
  // type === 'api_inbound_event' → outbound call ended on break — ignore
}

// Blindly clearing isReady on every logout kills the break session indicator
if (event.event_name === 'on_agent_logout_success') isReady = false

Network Disconnect — Don't Reset to Login Screen

When the network drops, on_disconnected fires. Resetting the UI back to the connect form loses the user's configuration and is disorienting. The SDK reconnects automatically — just show a status banner.

if (event.event_name === 'on_disconnected') {
  isDisconnected = true  // show banner: "Connection lost — reconnecting..."
  // keep SDK instance alive
}
if (event.event_name === 'on_registered') {
  isDisconnected = false // hide banner when reconnected
}

if (event.event_name === 'on_disconnected') {
  sdk = null             // destroys instance — user must re-enter credentials
  showLoginForm()
}

Handling on_initiate_failed

When an agent is in Ready state, outbound calls are blocked. The SDK fires on_initiate_failed with an explanatory message. Always handle this event — otherwise the UI gets stuck in a dialing state.

voice.on('sociomileEvent', (event) => {
  if (event.event_name === 'on_initiate_failed') {
    isDialing = false
    showToast(event.message) // e.g. "agent is ready, please enter break or unready state"
  }
})
on_initiate_failed fires before any SIP session is created. Do not attempt to call hangup() after this event — there is no session to hang up.

Use shallowRef for the SDK Instance

The SDK instance contains JsSIP internals (WebSocket connections, SIP UA, media streams). Wrapping it in Vue's deep-reactive ref() causes proxied getters/setters on those objects, which breaks SIP stack behaviour.

import { shallowRef } from 'vue'
const sdk = shallowRef(null)
sdk.value = new window.SocioVoice.Init({ ... })
sdk.value.start()

import { ref } from 'vue'
const sdk = ref(null)       // deep reactivity wraps JsSIP internals — causes subtle failures
sdk.value = new window.SocioVoice.Init({ ... })

Same rule applies to callSession and callSessionIncoming — keep them as plain let variables, not refs.

Filter High-Frequency Stats Events From Your Log

on_stats fires every second during a call. Piping it into an event log will flood the UI and make debugging impossible.

voice.on('sociomileEvent', (event) => {
  if (event.event_name === 'on_stats') {
    // Update stats display directly, don't log
    currentStats = event.data
    return
  }
  // All other events go to the log
  appendToLog(event)
})

Keep on_stats_running and on_stats_stop in the log — they mark when monitoring starts and ends.

Enumerate Audio Devices After Requesting Permission

navigator.mediaDevices.enumerateDevices() returns devices with empty label strings until microphone permission has been granted. Always request a temporary audio stream first, then enumerate.

async function getDevices() {
  // Trigger permission prompt — labels are populated after this
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true, video: false })
  stream.getTracks().forEach(t => t.stop()) // release immediately

  const devices = await navigator.mediaDevices.enumerateDevices()
  const mics = devices.filter(d => d.kind === 'audioinput' && d.deviceId)
  // d.label is now "Built-in Microphone", not ""
}

async function getDevices() {
  const devices = await navigator.mediaDevices.enumerateDevices()
  // d.label === "" for every device — useless for display
}

Also listen for devicechange to refresh the list when the user plugs in a headset:

navigator.mediaDevices.addEventListener('devicechange', getDevices)

on_fetch_breaks_success Returns an Object, Not an Array

The break list comes back as { "1": "Lunch", "2": "Short Break" }. Iterating it directly with .map() or .forEach() won't work.

if (event.event_name === 'on_fetch_breaks_success' && event.data) {
  breakList = Object.entries(event.data).map(([id, name]) => ({ id, name }))
  // → [{ id: "1", name: "Lunch" }, { id: "2", name: "Short Break" }]
}

Drive Hold and Mute State From SDK Events, Not Button Clicks

Local toggle state can desync from the SIP stack if the SDK call fails silently. Let SDK events be the source of truth.

// SDK fires confirmation events — update state only then
if (event.event_name === 'on_start_hold') isOnHold = true
if (event.event_name === 'on_end_hold')   isOnHold = false

// Button just calls the SDK method; state stays unchanged until confirmed
function onHoldClick() {
  isOnHold ? sdk.unhold() : sdk.hold()
}

function onHoldClick() {
  isOnHold = !isOnHold  // optimistic toggle — desync if SDK call fails
  sdk.hold()
}

Inbound Call Hold — Use inbound_event Type to Filter

on_hold_call_success and on_unhold_call_success can fire for both outbound and inbound sessions. Always check event.type === 'inbound_event' before updating inbound hold state, otherwise the button toggles on the wrong call.

if (event.event_name === 'on_hold_call_success'   && event.type === 'inbound_event') isOnHoldInbound = true
if (event.event_name === 'on_unhold_call_success' && event.type === 'inbound_event') isOnHoldInbound = false

// Hold button click — just call SDK, wait for event
function onHoldInboundClick() {
  isOnHoldInbound ? sdk.unholdInbound() : sdk.holdInbound()
}

// Toggling on click without waiting for SDK confirmation
function onHoldInboundClick() {
  isOnHoldInbound = !isOnHoldInbound
  sdk.holdInbound()
}

The hold button for inbound calls should only appear after on_agent_call_linked fires — that confirms the agent is connected to a queue call.
